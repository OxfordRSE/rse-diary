# RSE Diary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A personal RSE dev diary: agents log FTE/touch entries via a PAT-authenticated JSON API; a server-rendered, no-JS-required web UI shows a calendar heatmap, per-project progress and exports.

**Architecture:** One TypeScript Lambda (function URL) behind CloudFront handles HTML pages, form POSTs and `/api/*`. Handlers use web-standard `Request`/`Response`; a thin adapter converts Lambda function-URL events. Data is S3 JSON per user (`users/{sub}/…`) written with ETag-conditional puts. Terraform deploys everything from one root with `prevent_destroy` on the data bucket and user pool.

**Tech Stack:** Node 22, TypeScript 5, esbuild, vitest, `@aws-sdk/client-s3`, `aws-jwt-verify`, Pico CSS 2 (vendored), Terraform ≥1.6 with `hashicorp/aws` ~> 5.

**Spec:** `docs/superpowers/specs/2026-11-05-rse-diary-design.md`

## Global Constraints

- Every page and action works with JS and CSS disabled; JS/CSS only enhance.
- Semantic HTML: real `<table>` calendar, `<meter>` progress, `<details>`, `<dialog>`, `<time>`, plain forms with POST-redirect-GET.
- All HTML output escaped via one `html` tagged template; raw strings only via explicit `raw()`.
- S3 writes: `If-Match` etag or `If-None-Match: *`, retry on 412 up to 5 times with jitter.
- Users only ever touch `users/{their sub}/…`; no route takes a sub as input.
- PAT format `rsed_` + base64url(32 random bytes); store only sha256 hex.
- Touch = `fte: null`. `0 < fte <= 1`. Day total > 1 warns, never blocks.
- Name normalisation key: lowercase, strip non `[a-z0-9]`.
- Calendar: 26 weeks, Mon–Sun rows, ≥5 projects in a day → ✨, neutral grey ramp shade, project dots from non-grey palette.
- "Today" defaults to Europe/London date.
- `.log` line format exactly as spec §12.

## Review Focus

1. Concurrent agent writes to the same month file: neither entry lost (store test with interleaved writers).
2. Agent sends project name differing only in case/punctuation: resolves to existing project, never duplicates (`resolveProject` test).
3. Entry date in a different month from today / entries array spanning two months: each lands in its own month file (API test).
4. Notes containing `<script>` or `&`: rendered escaped in HTML, verbatim in `.log` (render + export tests).
5. Project with deadline in the past and entries after it, or no entries at all: span/bins compute without crashing (`projectSpan` tests).

}
class PreconditionFailed extends Error {}
class MemoryBlobStore implements BlobStore {}   // etag = incrementing counter
class S3BlobStore implements BlobStore { constructor(bucket: string, client?: S3Client) }
updateJson<T>(store, key, empty: () => T, fn: (cur: T) => T | Promise<T>): Promise<T>  // retry ≤5 on PreconditionFailed

class Repo {

### Task 6: API

**Files:** `src/api.ts`, `src/instructions.md`, `test/api.test.ts`

**Consumes:** Repo, tokens, totals, names, exports. **Produces:** `handleApi(req: Request, ctx: { repo: Repo; tokenLabel?: string; today: string }): Promise<Response>`.

Routes per spec §10. `POST /api/entries` algorithm:
1. Normalise body to array; validate each (date `YYYY-MM-DD`, fte null or 0<fte≤1, notes string ≤ 20k, project_id or project). Collect all errors → 422 `{error, detail: [{index, message, suggestions?}]}` before any write.
2. Resolve projects via `resolveProject(cfg, nameOrId) -> Project | null` (match id, then normalised name). Unknown + `create_project` → queued for creation.
3. `updateConfig` once to add new projects (re-resolve inside fn so a concurrent creator wins without dupes).
4. Group entries by month; `updateMonth` each. `client_id` match on same date → replace (keep id/created_at).
5. 201 `{entries, created_projects, warnings}` where warnings include days whose total FTE > 1.

### Task 7: Auth and web routes

**Files:** `src/auth.ts`, `src/web.ts`, `src/app.ts`, `test/web.test.ts`

**Produces:**
- `route(req: Request, deps: Deps): Promise<Response>` with `Deps = { store: BlobStore; cognito: CognitoCfg; verifyIdToken(t: string): Promise<{sub: string; email?: string}>; now(): Date; fetch: typeof fetch }`.
- Auth: `/api/*` accepts `Authorization: Bearer rsed_…` (lookupToken) or session cookie; web routes need the cookie, else 302 to `/login`.
- `/login` → 302 Cognito `/oauth2/authorize` (code, PKCE S256, state; verifier+state in short-lived `__Host-rsed_pkce` cookie). `/auth/callback` → POST `/oauth2/token`, verify id_token, set `__Host-rsed_id` (id token) and `__Host-rsed_rt` (refresh token) cookies `HttpOnly; Secure; SameSite=Lax; Path=/`; 302 `/`. Expired id token + refresh cookie → refresh via token endpoint transparently. `/logout` clears cookies → Cognito `/logout`.
- CSRF: non-GET web requests rejected 403 unless `Sec-Fetch-Site` is `same-origin`/absent and `Origin` (if present) matches host.
- Web routes: `GET /` (`day`, `p`), `GET /projects`, `GET/POST /projects/new`, `GET /projects/:id`, `GET/POST /projects/:id/edit`, `GET/POST /entries/new`, `GET/POST /entries/:id/edit`, `GET/POST /entries/:id/delete`, `GET /tokens`, `POST /tokens`, `POST /tokens/:hash/revoke`, `GET /export/summary`, `GET /projects/:id/export.log|.json`. Form POSTs → 303 redirect. Overview fragment: `GET /?day=…&fragment=day` returns only the day-entries section HTML (for JS swap).
